# Что делает приложение

Приложение контроля процесса — браузерное, на Nuxt 4, живёт отдельным
репозиторием и работает с любым проектом: пользователь указывает корень, дальше
всё читается из `docs/development`.

Этот документ — граница между приложением и файлами: что оно вправе прочитать,
что записать и чего не трогает никогда.

## Чтение

1. Читает `docs/development/project.yaml`, проверяет поколение контракта.
2. Обходит папки из `paths`, разбирает front matter каждого `*.md`.
3. Строит граф: узлы — записи, рёбра — связи из `links` плюс обратные.
4. Подтягивает отчёты прогонов из `tests/reports/`.
5. Проверяет схемы, ссылочную целостность и правила процесса.

Результат разбора кэшируется в `.docdd/index.json` внутри проекта. Кэш —
производное: удаляется без последствий, в git не попадает.

## Запись

Приложение пишет **только front matter и журнальные строки**:

| Что можно менять | Когда |
|---|---|
| `status` | Действия процесса: отдать на подтверждение, подтвердить, запустить в разработку, закрыть |
| `updated` | Вместе с любым изменением |
| `owner` | Назначение исполнителя |
| `links` | Добавление и снятие связи |
| `phase` | Перенос задачи в фазу |
| Раздел `## Журнал` | Строка о смене статуса |
| Новый файл | Создание записи из шаблона |

Чего приложение не делает никогда:

- не переписывает текст документа;
- не удаляет файлы — только меняет статус на `dropped` или `superseded`;
- не трогает код проекта;
- не делает коммитов, не создаёт веток, не запускает агентов и сборки.

Последнее сознательно: приложение отвечает за состояние работы, а не за её
выполнение. Кто и чем пишет код — не его дело.

## Запись как правка файла

Изменение статуса — это правка одного поля и сохранение файла. Значит:

- git видит обычный маленький дифф, историю ведёт он же;
- одновременная правка двумя людьми даёт конфликт git, а не потерю данных;
- откат — обычный откат файла.

Файл перезаписывается целиком, порядок ключей front matter сохраняется,
незнакомые поля остаются на месте. Перевод строки — как в исходном файле.

## Экраны

| Экран | Отвечает на вопрос |
|---|---|
| Обзор проекта | В каком состоянии работа: сколько задач в каждом статусе, что нарушает правила |
| Граф | Что на что опирается: требования, документы, задачи, проверки |
| Задача | Что делать, на чём основано, чем проверяется, журнал |
| Документ | Текст, диаграммы, кто на него ссылается, статус подтверждения |
| Требования | Покрытие: у каких есть проверки и каков их последний результат |
| Фазы | Состав и готовность |
| Нарушения | Список ошибок и предупреждений с переходом к записи |

## Работа с несколькими проектами

Список проектов хранится в настройках приложения: имя и путь к корню. Данные
проекта не копируются и не хранятся в приложении — источником остаётся
репозиторий.

## Доступ к файловой системе

Приложение браузерное, но файлы локальные, поэтому чтение и запись идут через
серверную часть Nuxt (Nitro), которая работает на машине пользователя. Наружу
она не смотрит: ни аутентификации, ни удалённого доступа в первой версии нет.

Ограничение, которое стоит принять сразу: **сервер работает только внутри
объявленного корня проекта.** Путь за его пределы — отказ.

## Чего в приложении нет намеренно

- Обсуждений и комментариев: для этого есть git и мессенджер.
- Учёта времени и оценок: они не проверяются фактом и быстро врут.
- Прав и ролей: инструмент однопользовательский, роли в файлах — это подпись, а
  не доступ.
- Правки текста документов: редактор у человека лучше.
