# 🎣 FishForecast: Стратегия развития

## 🎯 Vision & Core Value
Создание **автономного экспертного ассистента**. Приложение не просто показывает погоду, а интерпретирует её через призму ихтиологии, помогая рыболову принять решение "ехать или нет" в условиях полной изоляции от сети.

---

## 🏗 Техническая архитектура (Verified)
*   **Modern UI:** Jetpack Compose + **Type-Safe Navigation**.
*   **Reliable Data:** Room (SSOT) + DataStore (Settings).
*   **Predictive Core:** Clean Architecture (UseCases для расчета Bite Score).
*   **Offline First:** Retrofit + WorkManager для предзагрузки прогнозов на 7 дней.
*   **Sensors:** Интеграция системного барометра для уточнения прогноза.

### ✅ Фаза 3: Гео-визуализация (Offline Maps) (Done)
*   [x] **Шаг 1:** Интеграция MapLibre/OSM — экран карты, вкладка, центрирование по позиции.
*   [x] **Шаг 2:** Менеджер офлайн-областей (скачивание видимой рамки, прогресс, удаление).
*   [x] **Шаг 3:** Слой "Секретные точки" с привязкой к справочнику рыб.
*   [x] **Шаг 4:** Обмен данными — GPX-точки, снимок карты, выгрузка/загрузка офлайн-карт («Хранилище»).

> ℹ️ Источник карт: **OpenFreeMap** (данные OSM, без ключей и квот), задаётся
> в `ui/map/MapConfig.kt`. Демо-стиль MapLibre использовать нельзя — на нём
> офлайн-загрузка роняет процесс нативным `std::regex_error` в libmaplibre.
>
> ⚠️ Перед публикацией: подтвердить право на предзагрузку тайлов у источника
> либо перейти на свой хостинг PMTiles (Protomaps в R2 + Worker). Политика
> `tile.openstreetmap.org` предзагрузку прямо запрещает.
>
> ⚠️ Обмен картами: MapLibre не умеет выгружать области поштучно, поэтому
> наружу уходит вся база (`mbgl-offline.db`), а чужие области подмешиваются
> через `mergeOfflineRegions`. Оформление стиля при слиянии не переносится —
> чужую карту нужно один раз открыть при интернете, дальше она работает офлайн.
>
> ⏳ Офлайн-геокодинг (поиск водоёмов и обратный геокодинг без сети) требует
> отдельного индекса: `.pmtiles` и тайловый кэш отвечают только за отрисовку.
> План — SQLite рядом с областью: FTS по названиям + R-tree по координатам,
> индекс готовится заранее из `.osm.pbf` и качается тем же менеджером.

### ✅ Фаза 4: Аналитическое ядро "Bite Score" (Done)
*   [x] Разработка `CalculateFishActivityUseCase`.
*   [x] Алгоритм оценки давления (анализ градиента изменения за 3 часа).
*   [x] Визуализация: Графики активности по часам (вкладка «Клёв»).

> ℹ️ Оценка складывается из четырёх факторов с весами: температура (0.35),
> давление (0.30), тенденция за 3 часа (0.25), ветер (0.10). Каждый фактор
> возвращает пояснение, поэтому экран показывает причину, а не одно число.
>
> ⚠️ Упрощение: резкое изменение давления считается плохим в обе стороны.
> На практике падение перед фронтом часто наоборот активизирует хищника —
> уточнить, когда появится журнал трофеев и будет с чем сверять.

### ✅ Фаза 5: Экосистема рыболова (Done)
*   [x] Журнал трофеев (Photo + Weather Metadata) — привязан к `fishing_spots`.
*   [x] Smart Notifications: уведомление о ближайшем окне клёва.

> ℹ️ Улов сохраняет снимок условий того часа (температура, давление, ветер,
> оценка клёва). Это данные для будущей калибровки: сверив прогноз с реальным
> уловом, можно уточнить упрощение Фазы 4 про падение давления.
>
> ℹ️ `BiteAlertWorker` проверяет прогноз раз в 6 часов и при запуске
> приложения, ищет лучшее окно на сутки вперёд среди всех рыб справочника и
> зовёт один раз по самому весомому поводу. Сеть не нужна — считает по уже
> скачанному прогнозу.
